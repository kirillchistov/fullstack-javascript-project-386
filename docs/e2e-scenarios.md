# Интеграционные (e2e) сценарии и тест-кейсы

Проверяются в реальном браузере (Playwright + Chromium) против полного стека:
Fastify-бэкенд с хранилищем в памяти + Vite-фронтенд. Оба сервера поднимаются
автоматически при запуске тестов (`webServer` в [e2e/playwright.config.ts](../e2e/playwright.config.ts)).

Запуск: `cd e2e && npm test` (один раз перед этим — `npx playwright install chromium`).

## Реестр тест-кейсов

Формат — как в QA-командах: идентификатор, приоритет, предусловия, шаги,
ожидаемый результат, способ покрытия. Автоматизированные e2e-кейсы реализованы
в [e2e/tests/booking.spec.ts](../e2e/tests/booking.spec.ts); граничные условия
API покрыты юнит-тестами бэкенда ([backend/test/api.test.js](../backend/test/api.test.js),
15 сценариев через `fastify.inject` — без браузера быстрее и стабильнее).

## Что сознательно не покрыто e2e

- Границы периодов, валидация полей, пересечения правил — юнит-тесты бэкенда
  (см. таблицы выше): быстрее и без флаков браузера.
- Настройка доступности владельцем через UI (TC-13) — второстепенный сценарий,
  API-слой покрыт; добавим e2e при изменении этого экрана.

## Замечания по стабильности

- Тесты выполняются последовательно (`workers: 1`): бэкенд один на весь прогон,
  данные в памяти общие.
- Каждый тест использует уникальные имя/email гостя и «ближайший будний день»,
  чтобы не зависеть от порядка выполнения и текущей даты (расписание сида:
  Пн–Пт 10:00–18:00 Москвы). Ближайшие будние дни всегда внутри горизонта
  бронирования (14 дней).
