# Тест-кейсы: e2e, компонентные и юнит-тесты

Три уровня автоматизации:

- **e2e** (Playwright + Chromium против полного стека: Fastify-бэкенд +
  Vite-фронтенд, оба поднимаются автоматически через `webServer` в
  [e2e/playwright.config.ts](../e2e/playwright.config.ts)) — сквозные
  пользовательские сценарии. Запуск: `cd e2e && npm test`.
- **Компонентные** (Playwright Component Testing: страницы React монтируются
  в реальном Chromium, API мокается на уровне сети через `page.route`, бэкенд
  не нужен; [frontend/tests-ct/](../frontend/tests-ct/)) — состояния и логика
  UI, включая регрессы. Запуск: `cd frontend && npm run test:ct`.
- **Юнит-тесты бэкенда** ([backend/test/api.test.js](../backend/test/api.test.js),
  15 сценариев через `fastify.inject`) — бизнес-правила и граничные условия API.
  Запуск: `cd backend && npm test`.

Перед первым запуском Playwright-тестов: `npx playwright install chromium`.

## Реестр тест-кейсов

Формат — как в QA-командах: идентификатор, приоритет, предусловия, шаги,
ожидаемый результат, способ покрытия. E2e-кейсы реализованы в
[e2e/tests/booking.spec.ts](../e2e/tests/booking.spec.ts), компонентные (CT) —
в [frontend/tests-ct/](../frontend/tests-ct/).

## Распределение по уровням

- Сквозные пути пользователя (бронирование, конфликт, кабинет) — e2e:
  единственный уровень, который ловит рассинхронизацию фронтенда и бэкенда.
- Состояния UI (пустые списки, недоступные кнопки, ошибки в формах,
  переходы между шагами) — компонентные тесты: секунды вместо минут,
  моки API позволяют легко воспроизводить редкие ответы (409, 401, пусто).
- Границы периодов, валидация полей, пересечения правил, статусы ошибок —
  юнит-тесты бэкенда: быстрее и без флаков браузера.
- Настройка доступности владельцем через UI (TC-13) — второстепенный сценарий,
  API-слой покрыт; добавим тесты при изменении этого экрана.

## Замечания по стабильности

- E2e-тесты выполняются последовательно (`workers: 1`): бэкенд один на весь
  прогон, данные в памяти общие. Компонентные тесты изолированы (мокнутое API)
  и выполняются параллельно.
- Каждый e2e-тест использует уникальные имя/email гостя и «ближайший будний
  день», чтобы не зависеть от порядка выполнения и текущей даты (расписание
  сида: Пн–Пт 10:00–18:00 Москвы). Ближайшие будние дни всегда внутри горизонта
  бронирования (14 дней).
